# Adaptive-v2 native routing benchmark

Date: 2026-07-15

Adaptive-v2 is a versioned, self-describing candidate frame with four reversible
payload recipes: store, Zstandard level 3, LZ4 level 1, and 32-bit
delta-transpose plus Zstandard level 3. Balanced mode currently selects store,
Zstandard, or the specialized transform. The LZ4 recipe remains decodable and
reserved for a future fast mode because repeated validation did not justify it
for balanced mode.

The Zstandard path uses direct `libzstd` FFI. Codec-version discovery runs once
in the parent before timing and no longer launches discovery subprocesses in
isolated workers.

## Correctness and compatibility

- Version-1 adaptive frames continue to decode.
- Version-2 frames reject invalid version/backend combinations.
- Every frame retains original size and source SHA-256.
- The native Rust transform matches the Python reference byte for byte.
- Direct `libzstd` compression and decompression are covered by round-trip tests.

## Synthetic smoke result

The repeated heterogeneous smoke run completed 160 measured trials with zero
round-trip failures. Adaptive-v2 produced 30.72% of the original bytes, the
smallest aggregate output in that run, versus 31.23% for adaptive-v1 and 33.16%
for LZMA2 level 6. It passed selector overhead at 0.98% but reached only 75%
frontier coverage. This corpus is synthetic and cannot support an external
claim.

## Public starter result

The final repeated public-starter run used 8 digest-pinned real files,
17,792,077 source bytes, 72 warmup executions, and 160 measured trials.

## Decision

Keep adaptive-v2 as the candidate architecture, but do not claim that it beats
current general-purpose codecs. It demonstrates a real specialized ratio gain
on numeric and mixed synthetic inputs and matches Zstandard level 3 closely on
the current real-file aggregate. It does not meet the balanced product gate.

Frontier coverage varied materially across two-repetition runs even after
removing known discovery overhead. The next experiment is benchmark
stabilization: persistent native workers, at least five measured repetitions,
thermal/load recording, randomized codec order, and confidence intervals.
Threshold or backend tuning should pause until that measurement work is done.
