# JLS2 complete-product speed protocol

## Decision

Measure the exact experimental JLS2 product surface before opening blind
validation. This protocol supersedes using the inner JLC2 benchmark as the
product-speed gate.

No validation file may be downloaded, opened, or scored by this protocol.

## Frozen inputs

- corpus: `corpora/logtrie-train-v1/manifest.json`;
- accepted bytes:
  `runs/json-log-jlf2-jls2-16m-development.json`;
- gates: `config/jls2-product-gates.json`;
- segment target: 16 MiB;
- compression level: JLS2's versioned level-6 contract;
- repetitions: five after one warmup.

Every input file and protocol artifact is SHA-256 verified and recorded in the
result. The benchmark must run from a clean commit.

## Complete operation under test

Compression uses `compress_json_log_file` with a unique destination and the
default no-clobber publication path. The measured interval includes:

- source file reads;
- record-aligned segmentation;
- direct-Zstandard and JLC2 candidate work;
- exact smaller-frame selection;
- frame and stream SHA-256;
- temporary output writes and flush;
- atomic no-clobber publication.

Decompression uses `decompress_json_log_file` with an output bound equal to the
known source size. The measured interval includes:

- encoded file reads;
- stream and nested-frame verification;
- selected payload decode;
- exact JCT1 reassembly where selected;
- restored-output SHA-256;
- temporary output writes;
- atomic no-clobber publication.

Post-timing verification hashes every output and requires exact source bytes.

## Host eligibility

First run:

```text
scripts/wait-for-quiet-host.py \
  --gates config/jls2-product-gates.json \
  --consecutive 3 \
  --interval 10 \
  --timeout 600
```

The benchmark independently rechecks that one-minute load divided by logical
CPU count is at most 1.0 at process start. It aborts before touching corpus
payloads if the host is no longer eligible.

Record load at start, after every family, and at end. Load generated by the
benchmark itself is diagnostic and does not invalidate the qualifying
preflight.

## Timing and determinism

For each family:

1. verify the source digest and size;
2. warm compression and decompression once;
3. perform five complete file compressions to unique outputs;
4. require all complete encoded files to have the same SHA-256;
5. require size identity with the accepted JLS2 development artifact;
6. perform five complete file decompressions;
7. require every restored file to match the source size and SHA-256;
8. report median wall time and decimal MB/s;
9. atomically checkpoint the result.

Aggregate throughput uses total original bytes divided by the sum of family
median times.

## Frozen gates

- host preflight at or below 1.0 normalized load;
- clean commit;
- at least five repetitions;
- exact accepted encoded size on every family;
- deterministic encoded SHA-256 on every family;
- compression at least 75 MB/s on every family;
- aggregate compression at least 100 MB/s;
- decompression at least 250 MB/s on every family;
- no round-trip, integrity, or output-bound failure.

Failure is evidence, not an invitation to relax thresholds. A passing run
advances to independent log-specific competitor reproduction. It does not
authorize a state-of-the-art claim or opening the sealed validation split by
itself.
